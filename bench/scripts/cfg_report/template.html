Frozen-trunk CFG: FoldBench 인터페이스 결과

stage3-s1-001 5k의 trunk·confidence·distogram을 고정하고 diffusion head만 conditioning drop으로 5k step 더 학습한 두 run(zero / learned fill)을, 시작점과 메인 라인과 같은 interface 집합 위에서 비교합니다. 채점이 진행되는 동안 숫자는 바뀝니다.

체크포인트 계보

이 페이지에서 채점한 체크포인트 중단된 run (채점 안 함) 칩: CFG 가능 여부 · 수집된 interface (AbAg / PPI)

Guidance 없이 (W = 1)

모든 체크포인트의 unguided 결과. 공통 interface 집합은 절반 이상 수집된 행끼리 잡습니다.

Guidance sweep

W는 guidance scale, Drop은 unconditional branch가 비우는 범위입니다. 각 모델 묶음의 W = 1 행(색 띠)은 같은 모델의 unguided 결과입니다.

샘플을 늘릴 때 최고점이 오르는 속도

interface마다 25개 샘플 중 k개를 무작위로 뽑았을 때의 기대값(조합식으로 정확히 계산, 재표본 잡음 없음). k = 1은 Mean, k = 25는 Oracle과 같습니다. 기준선은 같은 모델의 W = 1(굵은 회색)입니다. Seed 축은 seed 단위(seed당 5개 샘플 전부)로 뽑은 값으로, trunk를 몇 번 돌리느냐에 해당합니다.

interface별 비교 (x = 기준, y = 비교 대상)

점 하나가 interface 하나입니다. 대각선 위는 비교 대상이 더 좋은 interface, 아래는 더 나쁜 interface입니다. 점선은 DockQ 등급 경계 0.23 / 0.49 / 0.80입니다. 색은 |Δ| > 0.05 기준의 좋아짐 / 나빠짐입니다. Max(Oracle, 25개 중 최고)와 Mean(25개 평균)을 나란히, Conf(모델이 고른 1위)도 함께 그립니다.

W = 1이 못 푼 interface를 다른 W가 푸는 경우

Oracle 기준(25개 중 하나라도 DockQ ≥ 0.23). 살아남은 같은 모델의 W = 1에서 실패하고 그 W에서 성공한 interface, 잃음은 반대입니다. 두 수가 비슷하면 기준선 근처 interface가 샘플링 운으로 넘나든 것에 가깝습니다. 각 행을 열면 interface별 최고 DockQ(성공 샘플 수)가 W = 1 → W로 나옵니다.

읽는 법

Oracle / Conf / Mean

interface마다 25개 샘플(seed 5 × sample 5) 중 정답 기준 최고 DockQ / ranking_score(0.8·ipTM + 0.2·pTM) 1위 샘플의 DockQ(동점은 평균) / 25개 평균. Succ는 그 DockQ가 0.23 이상인 interface의 비율(%).

Drop 범위

full: trunk pair 전체를 fill 값으로. abag: 항체–항원 체인 쌍 블록만. all: 모든 체인 간 블록. learned 모델은 비운 자리에 학습된 null_pair 벡터가 들어갑니다.

†와 공통 집합

†는 그 행의 interface가 아직 다 수집되지 않았다는 뜻입니다. 숫자는 표 안의 모든 (충분히 수집된) 행이 가진 interface만으로 계산하므로, 같은 표 안에서는 직접 비교할 수 있습니다. 먼저 끝나는 쪽이 큰 target이라 중간 집합은 큰 target으로 치우쳐 있습니다.

채점 코드

OST 2.11.1, eval_ost e35cde9(reference 체인으로 interface 매칭). stage1·stage2는 예전 OST 결과를 이 코드로 다시 집계한 값(-rescore)입니다.

Confidence head

frozen 두 run은 stage3-s1-001의 confidence head를 그대로 씁니다. Conf 열은 구조 생성과 샘플 선택 차이가 섞인 값이고, Oracle·Mean은 선택과 무관합니다.

굵은 값

표 안 각 열의 최댓값(공통 집합 기준).
